# MCP-сервер «Возможности AI»

Локальный MCP-сервер для каталога [`Возможности AI`](<../Возможности AI>). Он
превращает Markdown-описания и матрицы рисков в структурированные инструменты,
ресурсы и промпты, которые может использовать AI-ассистент.

Сервер работает по stdio, поддерживает MCP `2026-07-28` и legacy-версии
(`2025-11-25`, `2025-06-18`, `2025-03-26`, `2024-11-05`). Внешних зависимостей
нет — только Python 3.10+ и стандартная библиотека.

**Режим работы:** только чтение. Сервер не изменяет файлы, не ходит в сеть и не
выполняет команды.

## Быстрый старт

```bash
# Проверить, что каталог читается, и увидеть статистику
python3 mcp/server.py --check

# Запустить MCP-сервер (обычно его запускает MCP-клиент)
python3 mcp/server.py
```

Сервер сам находит каталог `Возможности AI` рядом с папкой `mcp`. Если каталог
лежит в другом месте, укажите его явно:

```bash
python3 mcp/server.py --catalog "/путь/к/Возможности AI"
# или
AI_CAPABILITIES_DIR="/путь/к/Возможности AI" python3 mcp/server.py
```

## Подключение

### OpenCode

Добавьте в `.opencode/opencode.json` (или в глобальный конфиг OpenCode):

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "ai-capabilities": {
      "type": "local",
      "command": ["python3", "/абсолютный/путь/к/ai-work-problems/mcp/server.py"],
      "enabled": true
    }
  }
}
```

Готовый шаблон — [`config.example.json`](config.example.json).

### Claude Desktop

В `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "ai-capabilities": {
      "command": "python3",
      "args": ["/абсолютный/путь/к/ai-work-problems/mcp/server.py"]
    }
  }
}
```

Для другого клиента нужна команда `python3 <путь>/mcp/server.py` с транспортом
stdio.

На Windows используйте `python` вместо `python3` и при проблемах с кодировкой
задайте `PYTHONUTF8=1`. Диагностические сообщения сервер пишет только в `stderr`,
поэтому они не ломают stdio-протокол; включить их можно переменной
`AI_CAPABILITIES_MCP_LOG=1`.

## Инструменты

| Инструмент | Параметры | Что возвращает |
|---|---|---|
| `list_capabilities` | — | Все категории, цели, количество рисков, число критических и максимальный балл |
| `get_capability` | `category`, `include_risks=true` | Описание категории, задачи, примеры и матрицу рисков |
| `list_risks` | `category`, `level`, `risk_category`, `min_probability`, `min_impact`, `min_score`, `query`, `sort_by`, `limit`, `offset` | Отфильтрованный список рисков |
| `get_risk` | `risk_id` | Один риск: оценки, уровень, категория, меры снижения, источник |
| `search_catalog` | `query`, `category`, `include_capabilities`, `include_risks`, `limit` | Полнотекстовый поиск по описаниям и рискам |
| `get_risk_scale` | — | Шкала вероятности, влияния и уровней риска |
| `get_overview` | — | Главный документ каталога целиком |

Идентификаторы категорий:

`automation`, `data-analytics`, `consulting`, `text-processing`,
`verification`, `media`, `files`, `development`.

Идентификаторы рисков — `<category>-<number>`, например `development-1`,
`files-2`, `automation-5`. Форматы `development:1` и `development#1` тоже
принимаются.

Уровни в фильтрах: `низкий`, `средний`, `высокий`, `критический` или
`low`, `medium`, `high`, `critical`.

### Примеры вызовов

```json
{"name": "list_capabilities", "arguments": {}}
{"name": "get_capability", "arguments": {"category": "development"}}
{"name": "list_risks", "arguments": {"level": "критический", "min_impact": 5}}
{"name": "get_risk", "arguments": {"risk_id": "files-1"}}
{"name": "search_catalog", "arguments": {"query": "утечка данных", "limit": 5}}
{"name": "get_risk_scale", "arguments": {}}
```

## Ресурсы

Сервер отдаёт исходные Markdown-документы и агрегированные представления:

| URI | Содержимое |
|---|---|
| `ai-capabilities://overview` | `Возможности AI/Описание.md` |
| `ai-capabilities://risk-scale` | Раздел со шкалой оценки рисков |
| `ai-capabilities://index` | JSON-индекс категорий и рисков |
| `ai-capabilities://categories/{category}/description` | Описание категории |
| `ai-capabilities://categories/{category}/risks` | Матрица рисков категории |
| `ai-capabilities://categories/{category}` | Описание и матрица одним документом |
| `ai-capabilities://categories/{category}/risks/{number}` | Карточка одного риска |

В `resources/list` перечислены 19 готовых ресурсов (обзор, шкала, индекс,
описания и матрицы всех восьми категорий). Параметризованные варианты доступны
через `resources/templates/list`.

## Промпты

* `analyze_scenario` — разобрать сценарий внедрения AI: определить применимые
  возможности, найти риски и предложить порядок действий.
* `review_capability_risks` — проверить матрицу рисков категории под конкретный
  контекст и получить таблицу «риск — меры — владелец — срок проверки».

## Как устроен каталог

Сервер читает:

```text
Возможности AI/
├── Описание.md                  # обзор и шкала рисков
├── <Категория>/
│   ├── Описание.md              # цель, задачи, примеры
│   └── Матрица рисков.md        # таблица рисков
└── ...
```

Каждая папка первого уровня с `Описание.md` или `Матрица рисков.md` становится
категорией. Название категории берётся из имени папки. Для известных восьми
категорий идентификаторы зафиксированы; для новых папок идентификатор строится
транслитерацией имени.

Парсер таблиц терпим к форматированию: поддерживает выравнивание, `---` и `--:`
в разделителях, лишние пробелы. Уровень риска пересчитывается по единой шкале
`вероятность × влияние`; идентификатор риска — `<id категории>-<номер>`.

Чтобы обновить данные, отредактируйте Markdown-файлы и перезапустите сервер:
каталог читается при старте.

## Разработка и проверка

```bash
# Все тесты (стандартная библиотека, без pytest)
python3 -m unittest discover -s mcp/tests -v

# Компиляция
python3 -m py_compile mcp/catalog.py mcp/server.py

# Статистика каталога
python3 mcp/server.py --check

# Список инструментов
python3 mcp/server.py --list-tools
```

Структура проекта:

```text
mcp/
├── server.py          # stdio-транспорт, инструменты, ресурсы, промпты
├── catalog.py         # разбор Markdown и модель каталога
├── config.example.json
├── README.md
└── tests/
    ├── test_catalog.py
    └── test_server.py
```

## Ограничения

* Поиск лексический, без семантических эмбеддингов: учитываются вхождения слов,
  а не смысловая близость.
* Сервер не вызывает LLM и не принимает решений за пользователя — он только
  предоставляет данные и промпты.
* Если в матрице есть несколько таблиц, берётся первая таблица с колонками
  «Риск» и «Вероятность».
* Абсолютные пути в ответах не возвращаются: источники указываются относительно
  корня каталога.
